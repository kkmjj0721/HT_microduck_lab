# 协作与审查规范

任务状态与阶段验收集中在 [开发流程与任务](development.md)，仓库约束见 [AGENTS.md](../AGENTS.md)。
并发子工作属于同一任务，同时最多一个任务处于进行中；简单修改不为并发强行拆分。

## 分工与文件归属

| 角色 | 负责内容 | 交付内容 |
|---|---|---|
| 主代理或统筹者 | 任务范围、接口、分工、资源、共享文件与最终验收 | 完整文件清单、集成结果、验证与审查结论 |
| 实现者 | 在约定文件内实现并验证，报告接口变化和阻塞 | 修改文件、行为/接口变化、实际命令与结果、遗留项 |
| 独立审查者 | 只读核对需求、最终文件和证据，报告问题并复核修复 | 有定位和依据的问题、严重程度、复核结论 |

分派前写清目标、允许修改的文件、只读上下文及已有用户修改、前置依赖、接口和验收条件。
共享文件指定唯一修改者，其他代理交回建议；修改范围需要扩大时先由统筹者调整归属。
接口先确定再实现，依赖真实产物的集成按顺序执行；接口改变时同步使用方，其他独立工作继续进行。
没有合理的并行子工作时可以串行，不能用人数替代设计或验证。

同一文件同一时刻只有一个修改者。共享工作区不并发切换分支、暂存或执行其他 Git 写操作，
不覆盖用户或其他代理的改动。子代理不自行扩大范围或继续分派，交回后由统筹者决定下一步。
GPU 等共享资源按预算调度，重型检查必要时串行；每个子工作使用独立的项目内临时路径。

## 集成与独立审查

实现者交回文件清单、关键接口、实际命令/结果、未执行检查及原因、遗留问题和参考依据。
统筹者核对归属与依赖后集成，读取完整文件及上下文，不能仅接受子任务的完成声明。
审查范围包含新建未跟踪文件；用 `git status --short --branch`、差异和
`git ls-files --others --exclude-standard` 辅助枚举，不把 `git diff` 当作完整文件清单。

大功能编码前先检查设计中的模块、接口、依赖和验收；稳定文件可先行审查，
最终审查必须覆盖全部交付。作者不能作为自己改动的独立审查者；角色可在不同文件之间轮换。
审查者默认只读，修复交回原实现者，再复核修复和受影响内容。

审查重点为需求和范围、模块依赖、配置与资源路径、异常边界、观测/动作/时序、
训练和导出兼容性、验证覆盖，以及来源是否支持判断、本机事实与外部结果/假设是否区分。
只提出有依据且可采取行动的问题，包含文件位置、触发条件、影响、依据及修复建议。

| 严重程度 | 判断与处理 |
|---|---|
| 阻塞 | 关键行为错误、重要接口不兼容或必要验收缺失；修复并复核后才能完成 |
| 一般 | 可复现的局部缺陷或违反明确约束；本次交付前修复并复核 |
| 建议 | 不影响正确性和既定验收的改进；不阻塞交付，可记入后续任务 |

与本次范围无关的已有问题单独记录；不能为通过审查降低验收标准，也不用个人偏好阻塞交付。
实现者修复后提供证据，原审查者复核；若范围或接口改变，同步设计并补查受影响模块。
审查后又有修改时复核新增差异及其影响，不无理由重复无关检查。

## 完成与交付

大功能或跨模块接口变更使用 [审查模板](review/TEMPLATE.md)，复用同主题记录；
小修改在任务完成记录中简述。结论明确区分“独立审查通过”“自审完成”和“审查未完成”，
没有独立审查时不得宣称通过，大功能缺少独立审查时不能标为完成。

统筹者确认验收相关问题已关闭、最终文件与验证覆盖一致，所有代理及检查进程已结束，
再按项目规则清理本次临时产物和字节码、更新任务状态并交付。
失败现场在排查完成前保留；需要保留的结果注明用途和路径，不执行全仓库清理。
内部设计、审查与复核不要求用户逐轮确认，也不授予提交、推送、合并或发布权限。
