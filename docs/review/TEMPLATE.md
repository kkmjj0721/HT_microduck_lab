# 审查记录：填写主题

> 大功能或跨模块接口变更复制到 `docs/review/<主题>.md`，复用同主题记录。
> 小修改在任务完成记录中简述，不为每轮审查创建新文件。

## 审查范围与证据

- 任务与设计：关联 [任务表](../development.md) 及对应设计。
- 实现者与独立审查者：作者不能作为该改动的独立审查者。
- 文件范围与基准：包含已有改动和新增未跟踪文件，说明实际阅读的最终内容。
- 验证证据：实际命令、环境、关键结果、未执行项及原因。
- 依据：参考项目版本/路径或论文章节、本机适用差异与待验证假设。

## 问题与修复复核

| 编号与程度 | 文件位置 | 触发、影响、依据及建议 | 修复与验证 | 复核者及状态 |
|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 待填写 | 待复核 |

按 [审查规范](../collaboration_review.md) 区分阻塞、一般与建议；没有确认问题时删除占位行并如实说明。
审查者默认只读，修复交回实现者，再由审查者检查修复及其影响。

## 最终结论

- 审查状态：待审查 / 修复中 / 待复核 / 独立审查通过 / 自审完成 / 审查未完成（填写实际状态）。
- 问题关闭情况及最终集成验证：说明最终交付是否全部被审查与验证覆盖。
- 限制与后续：区分范围外已有问题、未验证能力和待办；未关闭验收相关问题时不能标为通过。

审查通过不授予 Git 提交或发布权限，任务状态只在开发文档统一维护。
